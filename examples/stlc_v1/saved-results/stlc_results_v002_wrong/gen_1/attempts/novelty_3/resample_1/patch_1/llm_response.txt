For domain types being base types, we can generate literal of that type (e.g., for Int, integer; for Bool, boolean; for String). That's appropriate. Could also generate variable reference if variable in context of appropriate type, but easier to use literals.

Thus we can produce argument literals.

One nuance: When applying outermost lambda, we need argument of type D1. We'll generate that argument as literal of type D1. Then after applying we get term of type D2 -> ... -> B0. Then apply next lambda, etc.

Thus final term is nested application: (( ( ( (λ v1: D1 . λ v2: D2 . ... λ vn: Dn . base) arg1) arg2) ... argn). That's one application after each lambda, resulting in total L applications.
