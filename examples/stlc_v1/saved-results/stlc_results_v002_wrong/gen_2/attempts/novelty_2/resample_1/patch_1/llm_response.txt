Let me think about how to properly generate well-typed lambda calculus terms:

For a term to be well-typed:
- Literals have their corresponding types
- Variables must be in scope with the right type
- Lambda (λx:T. t) has type T -> type(t) where x is bound in t
- Application (t1 t2) requires t1 : A -> B and t2 : A, result is B

The key insight is that we need to track the type context (what variables are in scope with what types).

Let me design a better generator:

1. First, generate a type


2. Then generate a term with that type, maintaining a context of available variables

I'll track available variables in a context mapping names to their types, and randomly decide between generating a literal, using a variable from context, creating a lambda, or applying a function. The depth parameter controls how large the generated structures can grow.
