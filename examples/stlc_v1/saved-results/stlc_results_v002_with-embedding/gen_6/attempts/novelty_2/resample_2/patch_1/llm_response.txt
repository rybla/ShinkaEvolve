The problem is:
1. The recursion doesn't use the `depth` parameter properly to limit size
2. There's no mechanism to use variables that are introduced by lambdas
3. There's no application of lambdas to arguments
4. The type is always `Int -> ...` which is very restrictive

Let me design a better generator:

1. Use depth to control size - decrement depth with each recursive call
2. Create a context of available variables
3. Allow using variables from the context
4. Allow applying lambdas to arguments
5. Use different base types and function types

Here's my plan:
- Add a context parameter that tracks available variables (with their types)


- When depth > 0, introduce lambda terms that bind variables and add them to the context for recursive generation
- Apply bound variables to arguments from the context when possible
- Use depth to progressively build larger, more complex terms instead of always defaulting to simple literals

The key is tracking which variables are in scope so we can reference them, then using the depth counter to decide whether to create new bindings or use existing ones.
