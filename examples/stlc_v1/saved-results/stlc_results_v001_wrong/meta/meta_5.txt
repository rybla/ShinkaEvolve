# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- **Type-Driven Recursive Descent with Contextual Priority**: The most successful programs (Generation 2 and 4) utilize a target-type-driven approach. Generation 4 achieved the highest score (12.22) by prioritizing variable selection from the context that matches the `target_ty` before attempting to generate new subterms.
- **Budget-Based Complexity Control**: Using a numeric `budget` or `size_limit` to manage recursion depth is a recurring theme in successful programs. Generation 4 uses a budget of 85, which allowed it to reach an average term size of 13.22, significantly outperforming the shallow trees of Generation 0 (size 1.33).
- **Strategic Application Generation**: The current best program (Generation 4) uses a "callable lookup" strategy. When the budget is sufficient (>5), it searches the context for variables of type `Fun` that return the `target_ty`. This led to a high `applied_lambdas_proportions_average` of 0.58.
- **Weighted Type Generation**: Favoring function types (`Fun`) during the initial type generation phase (e.g., a 70% bias in Generation 4) creates more opportunities for complex lambda abstractions and applications, leading to a high unique subterm proportion (0.94).

- **Missing Imports and Logic Errors**: Generation 3 (contextual_backtracking_generator) failed entirely due to implementation errors (likely a missing `List` import or malformed fallback), demonstrating that even theoretically sound strategies for maximizing variable usage fail if the execution environment is not strictly respected.

## Implementation Insights

By naming variables based on context length (`f"v{len(ctx)}"`), it avoids name collisions and enables efficient lookup for type-matching variables, contributing to its 0.30 variable usage proportion.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. **Implement Multi-Step Function Application (Currying Support)**: The current "callable lookup" only searches for variables that return the `target_ty` directly. Extend this by searching for variables whose return type is another function that eventually leads to the `target_ty` (e.g., to get `C`, look for `A -> B -> C`). This would significantly increase `applied_lambdas_proportions_average` and `tm_sizes_average` by generating nested `App` nodes.

2. **Dynamic Budget Reallocation for Failed Lookups**: Currently, if a "callable lookup" or "matching variable" check fails, the budget is spent on a generic `App` or `Lam`. Instead, if a high-priority context lookup fails, redistribute that "saved" budget to the fallback branches to allow for deeper literal or lambda structures, ensuring the `tm_sizes_average` remains high even when the context is sparse.

3. **Introduce Type-Inhabitant Memoization**: To improve `unique_subterms_proportions_average` and efficiency, maintain a small cache of successfully generated terms for specific types within a single `generate_sample` call. When the generator needs a term of `arg_ty` for an `App` node, it can occasionally pull from this cache or slightly mutate a cached term, increasing structural complexity without risking type invalidity.

4. **Context-Aware Argument Selection**: In the `App` generation case, instead of generating a completely random `arg_ty`, prioritize selecting an `arg_ty` that is already "inhabited" by variables in the current `ctx`. This creates a virtuous cycle where `App` nodes are more likely to use `Var` nodes as arguments, directly boosting the `used_vars_proportions_average` beyond the current 0.30.

5. **Refine Lambda Shadowing and Variable Naming**: The current naming scheme `f"v{len(ctx)}"` is safe but predictable. Introduce a strategy that occasionally reuses names from outer scopes (shadowing) or uses more diverse naming patterns while maintaining a mapping of `name -> type`. This tests the robustness of the term structure and can lead to more complex, realistic lambda abstractions that better explore the unique subterm space.
